# 第 6 階段規格｜會議資料庫與內部檔案庫

2026-11-11 · 小高（Claude Code）撰寫 · 依據 [participant-execution-plan.md](participant-execution-plan.md) 第 3 節第 6 階段、待決 D8／D9（已定）

本文件是規格，不是實作授權。開工前須依 `AGENTS.md` 建立 exact-file Task Change Contract，並由 Jim 對下列保護範圍逐項授權。計畫中「現況」描述（會議存於 `workspace_states` 同一包 JSON、無檔案儲存）來自計畫文件，開工前須由 Investigator 回到程式碼核對。

## 1. 目標
開會的檔案、紀錄、決議有固定存放與查詢處；不再不知道傳到哪裡。

## 2. 範圍
**包含**：會議紀錄與決議、組織會議（不綁活動）、會議查詢、檔案庫（上傳與雲端連結並用）、版本、回收區、前台曝光旗標。
**不含**：參與者功能（第 1–5 階段）、文章管理與活動相簿前台（第 5 階段，之後沿用本檔案庫）、郵件寄送。

## 3. 建議拆成四個子任務（各自一張合約，前一個 PASS 才開下一個）
| 子任務 | 內容 | 保護範圍 |
|---|---|---|
| 6a 會議獨立資料表 | 會議從 `workspace_states` 搬到獨立表；既有資料搬移、備份、逐筆比對；可建立不綁活動的組織會議 | DB／schema／migration、`app/api/workspace/route.ts` |
| 6b 會議紀錄與決議 | 記錄人撰寫、主持人確認定稿、定稿後修改留版本；決議（內容、負責人、期限）可一鍵轉任務並互相連結；依活動／日期／關鍵字／負責人查詢 | API、前端會議頁 |
| 6c 檔案庫 | 上傳（R2）與雲端連結；分類、所屬、標籤、可見範圍；版本與「定稿」；回收區；活動頁「檔案」分頁、會議附件、全站檔案庫頁 | DB、API、Environment／Deployment（R2 綁定） |
| 6d 前台曝光旗標 | 檔案「公開到前台」；合約／財務類禁止；下架後直連網址立即失效 | API；實際前台顯示留待第 5 階段 |

## 4. 資料模型（草案，欄位名開工時依現有命名調整）
- `meetings`：id、activity_id（可空）、日期、議程、主持人、記錄人、狀態（草稿／定稿）、建立與更新時間。
- `meeting_minutes_versions`：meeting_id、版本號、內容、作者、時間（只新增）。
- `meeting_decisions`：meeting_id、內容、負責人、期限、linked_task_id（可空）。
- `files`：id、名稱、分類（會議資料／文件／文宣／照片／合約財務／其他）、所屬類型與 ID（活動／課程／會議／組織）、儲存方式（R2／雲端連結）、R2 key 或連結、上傳者、標籤、可見範圍、是否公開到前台、刪除時間（回收區）。
- `file_versions`：file_id、版本號、R2 key、是否定稿、上傳者、時間（舊版保留）。

## 5. 權限（沿用計畫第 4 節）
- 會議紀錄撰寫／定稿：管理員全部；總召授權活動；見習總召指定活動；組長／一般成員僅被指定為記錄人或主持人。
- 會議紀錄查看：加上「自己出席的會議」。
- 檔案可見範圍：綁活動者跟活動職權；組織檔案三級（全體內部／總召以上／僅管理員）；合約財務預設僅管理員。
- 永久刪除：僅系統管理員。
- 所有權限判斷在後端，直接檔案網址也套用，不只隱藏按鈕。

## 6. 驗收
**正例**
- 既有會議搬移後數量與內容與搬移前備份逐筆一致。
- 記錄人寫、主持人定稿，定稿後修改產生新版本且舊版可查。
- 決議轉任務後，兩邊互相連結且點得到。
- 各角色只看到可見範圍內的會議紀錄與檔案。
- 回收區還原正確；公開到前台的檔案可被未登入者取得。

**反例**
- 無權限角色以直接網址取檔被拒（含 R2 簽名網址過期後）。
- 合約／財務類檔案無法設為公開。
- 公開檔案下架後，原直連網址立即失效。
- 非管理員無法永久刪除。
- 同一會議兩人同時存檔不會靜默覆蓋（需版本衝突處理）。
- 上傳大小與類型超限被拒（限制值開工時與 Jim 定）。

**回歸**：內部登入／登出、導覽、RBAC、任務中心、活動與既有會議顯示行為不變；一律使用隔離 D1，禁止正式 D1。

## 6A. 現況核對（2026-11-11，commit 12b0823，唯讀）
- 會議確實存在 `workspace_states` 那包 JSON（`app/api/workspace/route.ts:6`），欄位為 id、title、activityId、time、status 必填；type、organizer、recorder、endTime、location、meetingLink、agenda 選填（第 308–309 行）。**沒有會議紀錄、決議、附件欄位**。
- `activityId` 目前是必填字串，故「不綁活動的組織會議」需改驗證，也影響前端與既有 `confirm_meeting`／`update_meeting_attendance` 動作及活動職權判斷（第 166–229 行）。
- 該 API 一次整包比對 `activities/tasks/meetings/notices`（第 86、152 行），把會議拆出去時這段比對與權限邏輯必須一併調整，是 6a 的主要風險。
- 現有 migration 到 `0011_registration_qr_tokens.sql`，都屬第 1 階段；6a 會是 0012 以後，**與小嘉後續 migration 同編號衝突**，需等她那邊收斂或先約定編號。
- 專案內沒有 R2 設定（`wrangler*` 與 `package.json` 無命中），檔案儲存需新增綁定。

## 7. 風險與前置
- **與第 1 階段的衝突**：兩者都要動 schema／migration。開工前確認 migration 編號與分支策略，建議第 1 階段合併後再開 6a，或先約定編號區間。
- **資料搬移不可逆風險**：6a 搬移前完整備份，保留舊 JSON 欄位至驗收完成才清除。
- **R2 與環境變數**：需 Jim 決定架設方式（待決 D1）後才能設定 R2；在此之前 6a、6b 可先行。
- **前台曝光與個資**：公開檔案（尤其含人像的照片）須對齊個資草稿的照片告知。
