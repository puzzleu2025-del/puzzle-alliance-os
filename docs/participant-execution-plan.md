## 1. 已確認決策

### 身分
- **兩套身分完全分開**：內部人員（現有 `members` 六層角色，帳密登入）與聯盟名單參與者（Google 登入）。資料、權限、統計、積分各自獨立；信箱相同也不串接。
- 不考慮沒有 Google 帳號的訪客。

### 報名
- 內部會員以會員帳密登入後報名，**表單自動帶入會員資料**；一般訪客以 Google 登入後報名。
- 報名名單是**同一份**，畫面不依報名方式分類；後端每筆報名仍記錄所屬帳號（會員或參與者擇一），供分開統計與積分使用。

### 簽到
- 由工作人員掃描個人 QR；**會員與訪客的 QR 在同一個掃描介面處理**。
- 報名完成即顯示個人 QR；未保存者現場找工作人員，登入後直接進入「我的 QR」頁。
- 簽到名單以該場報名名單為準；未報名者由工作人員現場補登記後再簽到。

### 課程
- 同一種課程可在不同期間重複開（例：同內容 AI 課程 11 月、12 月各開一次）。

### 積分
- 參與活動、課程、協助辦理及貢獻可得分；內部人員也累積積分，兩套分開記帳。
- 內部一般成員以上以**協助辦活動**得分為主，參與給分較少。
- **必須報名且簽到**才給參與／課程積分。
- 同一課程不同梯次重複參加，**預設每期都給**。
- 積分目前不設期限；預留兌換。
- **所有分數與條件由系統管理員在後台設定調整，不寫死在程式。**
- 積分功能上線前的出席**不補發**。

### 問卷
- 活動負責人只對**已簽到**者發問卷；參與者登入後收到提醒；後台可看填寫進度。

### 前台
- 未登入公開頁、參與者前台、內部可設定前台內容、內部預覽前台；可顯示活動照片紀錄。
- 前台公開範圍由系統管理員在後台調整。

## 2A. 2026-11-11 方向更新（Jim 確認，優先於本文件其他段落）

| 主題 | 決策 | 對計畫的影響 |
|---|---|---|
| 組織型態 | 單一組織，以吸收他人加入成長 | 維持六層角色，不加「單位」層 |
| 參與者轉會員 | 參與者可申請成為一般會員；組長以上的條件保留（之後可能綁定協會）；加入後要能併入訪客時期資料 | 修正「兩套身分永不串接」：預設分開、不自動配對；**只有經核可的加入流程**才把參與者連到會員，並保留雙方原始紀錄、可追溯。第 1 階段資料模型要預留這個連結 |
| 公開前台 | 定位為聯盟官網，角落保留登入入口；報名由推廣內容點入 | 第 5 階段擴大為「官網內容管理」（介紹、消息、推廣等）；每個活動要有可被推廣連結的報名頁 |
| 積分 | 兩類：組長以上換內部貢獻度（未來可能分紅）；外部參與者與一般成員為其他獎勵（保留窗口） | 積分依「類別」分帳，不依身分分帳。貢獻度未來可能牽涉分紅，需有核准、不可竄改、本人可查明細 |
| 收費 | 建立活動時設定收費與否；金額於規劃時定，臨時變更需管理員；目前匯款核對帳號，線上付款保留窗口 | 活動加收費設定；報名加付款狀態與匯款資訊；金額變更權限比照設定鎖定 |
| 課程 | 循環課程（如 10 堂）與單節課程；出席每堂個別計算 | 新增「場次」層：活動／課程底下有 1 到多個場次，簽到依場次記錄；此結構須在第 2 階段開工前定案 |
| 統計 | 不論訪客或內部人員，報名後都要能看整體參加情況 | 統計後台增加「全體參加概況」（訪客＋內部合併視圖，仍可分開篩選） |
| 名單 | 建立總訪客名單；完整總會員名單與總訪客名單只有管理員可看 | 現行程式衝突：總召目前能看到所有組長與一般成員的完整資料（含聯絡方式），需調整；其他人只看到被授權活動相關的人 |
| 總召可見範圍 | 總召只看得到「待核可的申請」及「參與自己授權活動的人」 | 調整 `app/api/members/route.ts` 的列表範圍（受保護 API，需獨立任務合約）；指派任務用的姓名清單維持 |
| 積分升級 | 一般成員、組長、見習總召可靠積分升級；條件由管理員設定，管理員也可直接授權升級 | 第 3 階段加「升級規則」設定與「符合升級條件」名單。建議達標後由管理員確認才生效，不自動升級，因為升到總召會取得報名個資權限 |
| 未付款簽到 | 匯款核對前即可發 QR；簽到掃描時跳出未付款提示 | 第 2 階段掃描結果新增「未完成付款」提示，由工作人員決定是否簽到，紀錄保留簽到當下的付款狀態 |
| 會議與檔案庫 | 加入會議資料庫與內部檔案庫；檔案上傳與雲端連結兩者並用；可見範圍採小高建議的預設 | 第 6 階段（D8、D9 已定） |
| 前台曝光與文章 | 檔案可設定曝光到前台；前台可設置文章 | 檔案多一個「公開到前台」範圍；第 5 階段加入文章管理，封面與內文圖片取自檔案庫 |

## 3. 分階段執行計畫

每階段都是一張獨立任務合約，前一階段 PASS 且 Jim 驗收後才開下一階段。

### 第 0 階段：前置準備（不寫功能程式）

| 項目 | 負責 | 完成條件 |
|---|---|---|
| 決定自行架設方式（自有 Cloudflare 帳號或其他主機）與正式網域 | Jim | 有明確答案 |
| 申請 Google OAuth 用戶端，設定正式與測試回呼網址 | Jim | 用戶端 ID 存於秘密環境變數，不進 repo |
| 擬定個資告知與同意條款、照片肖像權文字 | 小嘉擬稿、小高審、Jim 定稿 | 文字定稿 |
| 隔離 D1 建立回歸基準：內部登入／登出、導覽、RBAC、報名、主要頁面 | 小嘉 | 基準回歸 PASS，並保存截圖 |
| 現有功能補驗收：兩台真實裝置、不同角色 | Jim | 驗收紀錄 |

### 第 1 階段：參與者身分與統一報名

**交付內容**
- `participants`、`participant_sessions`：用 Google `sub` 辨識帳號，伺服器驗證 Google 登入憑證，站內另發 session。
- 參與者前台最小版：登入、我的報名、我的 QR、個人資料、撤回同意。
- 統一報名：會員帳密或 Google 擇一登入；會員自動帶入資料，訪客帶入 Google 姓名與信箱及上次填寫的資料。
- 報名紀錄關聯所屬帳號（會員 ID 或參與者 ID，擇一必填）；同一場同一人只能有一筆有效報名。
- 報名完成即產生該場個人 QR（隨機代碼，後端存雜湊，可撤銷）。
- 加入聯盟名單的同意紀錄（同意時間、條款版本）。

**動到的保護範圍（需 Jim 授權）**：`app/page.tsx` 入口分流、Auth/session、報名 API、D1 schema/migration、環境變數（Google 用戶端）。

**驗收**
- 正例：會員登入報名會自動帶入資料；訪客 Google 登入報名；報名後立即看到 QR；重新登入能找回 QR。
- 反例：同信箱的會員與參與者是兩個獨立身分；同一場不能重複報名；參與者 session 打不開內部後台；未登入不能報名新活動。
- 回歸：內部登入、導覽、RBAC、既有報名表與舊連結行為不變。

### 第 2 階段：QR 簽到與課程梯次

**交付內容**
- 統一掃描頁（放在內部後台，手機可用）：掃描後顯示姓名、已報名、已簽到過或未報名。
- 掃描權限：預設為該活動的總召、見習總召及管理員；另可由管理員授權指定工作人員。
- 現場補登記：已登入但未報名者，由工作人員補登記報名後再簽到，並保留操作者與原因。
- 內部人員 QR：簽到時記錄當天身分（總召／工作人員／出席），出勤另外統計。
- 課程範本：可從範本一鍵開新梯次（帶入內容、報名表、積分設定），每個梯次是一場獨立活動。

**驗收**
- 正例：同一介面能掃會員與訪客；補登記可追溯；從範本開出的新梯次可獨立報名與簽到。
- 反例：錯場的 QR、已撤銷的 QR、無權限的工作人員都被拒絕；兩台裝置同時掃描只產生一次簽到。

### 第 3 階段：積分

**交付內容**
- 積分流水帳：只新增不修改，記錄正負分、類型、來源事件、規則版本、操作者、理由；餘額由加總算出。會員與參與者分開記帳。
- 系統管理員的積分設定頁：

  | 設定項 | 預設 |
  |---|---|
  | 各類型分數（活動、課程、協助辦理、問卷、貢獻） | 由管理員填 |
  | 內部與參與者分開設分 | 可以分開 |
  | 同一課程重複參加是否給分 | 每期都給（可改為只給第一次，或設上限） |
  | 個別活動或課程範本覆寫分數 | 沿用預設 |
  | 有效期限 | 不設（預留欄位） |

- 固定門檻（不可設定）：參與／課程積分必須報名且簽到。
- 自動入帳：簽到成功後依規則入帳；同一事件只入帳一次。
- 協助辦活動積分：活動結束後，負責人確認協助名單後入帳。
- 貢獻分：手動給分，必須寫理由（上限與核准方式見待決 D4）。
- 更正：以反向沖銷紀錄處理；規則變更只影響之後的入帳。
- 前台和後台都能查看積分餘額與明細。

**驗收**：重試不重複發分；修改規則不影響歷史紀錄；沒有簽到就不給分；兩套身分的積分互不相通；上線前的出席沒有積分。

### 第 4 階段：問卷與統計

**交付內容**
- 問卷：依已簽到名單產生收件人；登入時提醒；設截止時間；每人一份；後台顯示應填人數、已填人數、填寫率、未填名單，可再次提醒。
- 題型沿用報名表題型，加入 1–5 分評分與 0–10 推薦度。
- 統計後台：
  - 參與者個人頁：首次與最近一次參加、報名數、出席數、出席率、活動清單、平均滿意度、積分。
  - 內部人員出勤：場次、出勤率、擔任身分。
  - 每場活動：報名數、簽到數、出席率、新參加者比例、滿意度、問卷填寫率、發出積分。
  - 課程範本：跨梯次彙總。
  - 整體：重複率、回流率、每月新進人數。

**驗收**：有報名但未簽到的人看不到也送不出問卷；內部出勤不混入參與者統計；統計數字與原始紀錄一致。

### 第 5 階段：公開前台與活動照片

**交付內容**
- 未登入公開頁：活動列表、活動介紹、報名入口、聯盟簡介。
- 前台設定（系統管理員）：哪些活動公開、公告、橫幅、報名開放時間。
- 文章管理：類型有最新消息、活動回顧、公告、專欄；可連結活動或課程，文末帶報名按鈕；封面與內文圖片取自檔案庫。
- 文章流程：草稿 → 送審 → 發布（可排程）→ 下架；發布後修改保留版本。建議總召可為授權活動寫稿送審，由管理員發布（待確認 D10）。
- 前台顯示：首頁最新文章、文章列表依類型篩選、單篇文章頁；未發布或已下架的文章，前台與公開 API 都拿不到。
- 活動相簿：存放於 R2；可設公開、登入後可看、僅內部三種範圍；可下架單張照片。
- 內部預覽：用訪客視角的唯讀預覽，不冒用他人身分登入。
- 公開 API 只輸出允許公開的欄位；照片直連網址也套用相同的發布規則。

**驗收**：同一活動切換公開設定後，分別以未登入、參與者、內部三種身分驗證頁面、API 與照片網址；隱藏前台與關閉報名可各自獨立運作。

### 第 6 階段（獨立軌道）：會議資料庫與內部檔案庫

Jim 2026-11-11 新需求：避免每次開會的檔案、文件、文宣不知道傳到哪裡。本階段不依賴參與者功能，可在第 1 階段後平行進行；建議排在第 5 階段之前，讓活動相簿直接沿用檔案庫。

**現況**：會議和活動、任務一起存在 `workspace_states` 的同一包 JSON；每場會議只有議程、主持人、記錄人、連結，沒有會議紀錄、決議與附件，且必須綁定活動。系統沒有任何檔案儲存。

**交付內容（小高建議，方向待 Jim 確認 D8、D9）**
- 會議紀錄：記錄人會後撰寫，主持人確認後定稿；定稿後修改保留版本。
- 決議事項：每條有內容、負責人、期限；可一鍵轉成任務中心的任務，兩邊互相連結。
- 組織會議：可建立不綁活動的會議（例：月會、幹部會）。
- 會議查詢：依活動、日期、關鍵字、決議負責人搜尋。
- 檔案庫：每個檔案記錄名稱、分類（會議資料、文件、文宣、照片、合約／財務、其他）、所屬（活動、課程、會議或組織）、上傳者、時間、標籤、可見範圍。
- 版本：同一份文件或文宣可上傳多版，標記「定稿」，舊版保留。
- 入口：活動頁新增「檔案」分頁；會議卡片顯示附件；另有全站檔案庫頁面依分類與所屬瀏覽。
- 刪除：先進回收區，只有系統管理員可永久刪除。
- 活動照片沿用同一檔案庫，前台相簿只顯示標記為可公開的照片。
- 前台曝光（Jim 11/11 確認）：檔案除三級內部範圍外，可再設為「公開到前台」，例如文宣、簡章、照片供前台下載或顯示。合約／財務類不可公開；公開檔案下架後直接網址立即失效。

**資料與保護範圍**：會議改存獨立資料表（會議紀錄會變長，整包 JSON 易衝突），需 Jim 授權 DB/schema、`app/api/workspace/route.ts` 與既有會議資料搬移；檔案儲存需新增 Cloudflare R2（或 D8 決定的方式），屬 Environment／Deployment 保護範圍。搬移前先備份，搬移後逐筆比對。

**驗收**：既有會議搬移後數量與內容一致；不同角色只看得到可見範圍內的會議紀錄與檔案（含直接檔案網址）；決議轉任務後兩邊連結正確；回收區還原與永久刪除權限正確。

### 之後
寄送 QR、提醒與問卷信件（需郵件服務）；積分兌換；會場離線簽到。

## 5. 每階段的工作流程

```
Jim 指派階段
→ 小高把本計畫該階段寫成規格與驗收清單
→ Jim 授權本階段的保護範圍
→ 小嘉：retrieve → begin → exact-file 合約 → execute
→ 小嘉：diff、隔離 D1 回歸（正例、反例、既有功能）
→ 小高獨立審查：approve／revise／reject
→ PASS 後執行 complete、gate，再提交
→ Jim 授權後推送、部署
→ Jim 以真實裝置、不同角色驗收
→ 更新專案狀態（state_memory，比對 revision）
```

- 測試只用隔離 D1，禁止使用正式 D1。
- 每階段都有獨立開關，出問題時可以關閉新入口，保留已產生的紀錄。
